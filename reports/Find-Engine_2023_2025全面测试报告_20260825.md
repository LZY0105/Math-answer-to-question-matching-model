# Find-Engine 2023/2025 全面测试报告

- 测试日期：2026-08-25
- 引擎代码提交：`f84225a34203f0ca4f0857136971ff8a585638a0`
- 当前 GitHub `main`：`1e0e9bb3c608d7c33845d0d3f9834995c2a0ecb9`（仅新增中英文 README，算法代码未变）
- 测试方式：桌面全书批量测试；按用户补充要求，未进行平板测试
- 核心原则：错配比拒配更严重；“无法独立验证的已接受结果”按严格口径计为不正确

## 一、结论

当前版本只在“同一本 2023 习题册与答案册、双方都有题级书签”时表现可靠：508/508 个唯一题号全部覆盖，已验证匹配精确率 100%，没有错配。

但它尚未满足“错书、双答案、扫描版必须安全拒绝”的产品要求，存在三个发布阻断问题：

1. 跨年份错配没有被拒绝。2023 习题配 2025 答案产生 872 次 `HIGH` 错误接受；反向产生 479 次 `HIGH` 错误接受。
2. 双答案没有被拒绝。四种同年/跨年双答案组合均产生大量 `HIGH` 匹配。
3. 2025 扫描版习题没有题级书签和可用正文，引擎却把 18 个章节号当成题号；在“双方保留书签”时产生 479 次 `HIGH` 错误接受，真实题目召回为 0/573。

因此，当前版本不适合以“错配为零、安全拒绝”为验收标准发布。它的题级书签快速路径很好，但文档身份门控、角色门控、章节/题目书签分类和 OCR 接入还未完成。

2023 的金标准来自两本书各自独立的题级书签树，题号范围为 `1.1` 至 `2.231`。2025 答案册的 573 个题级书签与既有清单一致（数学分析 314 题、高等代数 259 题）；习题册只有章节和“计算题/证明题”书签，正文基本为扫描图像。

## 三、现有仓库测试

直接逐项运行仓库六套测试，结果为 138 项通过、0 项失败：

- question matcher：53/53
- answer index：29/29
- lazy text / OCR seam：12/12
- glyph map：13/13
- real PDFs：22/22
- no bookmarks：9/9

这说明单元级约束和原有 2023/2024 基线没有回归，但不能证明本次新增场景安全。原无书签测试对部分路径按每 8/16 页抽样，并把“无法由书签金标准识别的已接受条目”单列为 `unidentifiable`，未计入精确率分母，因此仍可能显示 100% 精确率。

## 四、2023 正确配对：书签与无书签

“已接受次数”按页面统计；同一道跨页题可能出现多次。“唯一召回”按 508 个真实题号统计。“严格精确率”把无法由独立书签金标准确认的已接受条目视为不正确。

| 习题书签 | 答案书签 | 已接受 | 独立确认正确 | 无法确认 | 严格精确率 | 唯一召回 | 拒绝 | p95/页 |
|---|---|---:|---:|---:|---:|---:|---:|---:|
| 有 | 有 | 872 | 872 | 0 | **100.0%** | **508/508（100.0%）** | 0 | 0.017 ms |
| 有 | 无 | 14 | 14 | 0 | **100.0%** | 8/508（1.57%） | 858 | 124.9 ms |
| 无 | 有 | 732 | 544 | 188 | **74.3%** | 400/508（78.74%） | 182 | 380.9 ms |
| 无 | 无 | 74 | 67 | 7 | **90.5%** | 50/508（9.84%） | 840 | 45.7 ms |

主要发现：

- 双方都有题级书签时，准确率、召回率和性能都很好。
- 答案册失去书签后，召回几乎消失，即使习题册书签完整也只覆盖 8 个唯一题号。
- 习题册失去书签后，正文解析得到 730 个候选，而真实题目只有 508 个；188 次已接受结果无法由独立金标准确认。若仍把这些结果展示给用户，严格精确率只有 74.3%。
- “无习题书签、有答案书签”路径 p95 为 380.9 ms，最大单页 1,534.6 ms，已触及当前约 1,500 ms 的对齐时限。

## 五、2025 正确配对：扫描版与章节误识别

2025 习题册没有题级书签，465 页只抽取到 609 个字符。四种组合均没有识别出任何真实题目，唯一题目召回为 0/573。

| 习题书签 | 答案书签 | 引擎候选 | 已接受 | 置信度 | 真实题目召回 | 评价 |
|---|---|---:|---:|---|---:|---|
| 章节书签 | 题级书签 | 18 | 479 | 479 `HIGH` | **0/573** | 严重误配：章节号当题号 |
| 章节书签 | 无 | 18 | 0 | 全部拒绝 | **0/573** | 安全但不可用 |
| 无 | 题级书签 | 18 | 14 | 14 `LOW` | **0/573** | 目录页编号被当题号 |
| 无 | 无 | 18 | 4 | 4 `MEDIUM` | **0/573** | 目录页编号被当题号 |

人工抽样复核进一步确认了误判性质：

- 习题册第 59 页实际是例题 `1.78`、`1.79`，引擎却把章节 `1.2 一元函数微分学` 当作题目 `1.2`。
- 习题册第 400 页实际是例题 `2.187`、`2.197`，引擎却把章节 `2.7 线性变换` 当作题目 `2.7`。
- 习题册第 4 页与答案册第 5 页可人工看到真实的例题 1.1，但当前引擎随后把章节 1.1 的整段页范围都指向答案 1.1，造成大量重复 `HIGH` 结果。

这不是 OCR 准确率偏低，而是当前宿主路径没有接入 OCR：`createTextSource` 提供了 recogniser 接口，但应用的 `PdfWorkspace` 未调用它。与此同时，稀疏文本层因为存在章节书签而被视为可用，导致本应返回“需要 OCR”的文档继续进入匹配。

## 六、答案与习题不符时的拒配矩阵

所有跨书和同类文档测试均使用原始书签。对错误组合，正确结果应为“整书拒绝，已接受 0，`HIGH` 0”。

| 场景 | 已接受 | `HIGH` | 整书拒绝 | 结果 |
|---|---:|---:|---|---|
| 2023 习题 → 2025 答案 | 872 | 872 | 否 | **失败** |
| 2025 习题 → 2023 答案 | 479 | 479 | 否 | **失败** |
| 2023 答案 → 2023 答案 | 861 | 861 | 否 | **失败** |
| 2025 答案 → 2025 答案 | 889 | 889 | 否 | **失败** |
| 2023 答案 → 2025 答案 | 861 | 861 | 否 | **失败** |
| 2025 答案 → 2023 答案 | 786 | 786 | 否 | **失败** |
| 2023 习题 → 2023 习题 | 0 | 0 | 是 | 通过 |
| 2025 习题 → 2025 习题 | 0 | 0 | 是 | 通过 |
| 2023 习题 → 2025 习题 | 0 | 0 | 是 | 通过 |
| 2025 习题 → 2023 习题 | 0 | 0 | 是 | 通过 |
| 2023 答案 → 2025 习题 | 0 | 0 | 是 | 通过 |
| 2025 答案 → 2023 习题 | 0 | 0 | 是 | 通过 |

双习题能被拒绝，是因为界面只检查右侧文档是否标记为答案册；左侧是否真的是习题册没有检查，所以双答案全部通过。

`indexesComparable` 也不能承担书籍身份判断。2023 习题与错误的 2025 答案字符表重叠率达到 0.9638，被判为 comparable；同为中文数学书时，字符表相似只说明文本可比较，不说明两本书配套。

## 七、总体评价

| 能力 | 评价 |
|---|---|
| 同书、双方有题级书签 | 优秀：100% 唯一召回、零错配、速度快 |
| 一侧无书签 | 召回和/或严格精确率不足，尚不可作为稳定主路径 |
| 双方无书签 | 召回仅 9.84%，且仍有不可独立确认的接受结果 |
| 扫描版 | 当前宿主未接 OCR；章节会被误当题目，存在 `HIGH` 错配 |
| 跨书错配拒绝 | 失败 |
| 双答案拒绝 | 失败 |
| 双习题拒绝 | 通过，但依赖单侧角色检查 |

综合判断：算法已经有一个质量很高的“题级书签快速路径”，但还不是一个安全的通用题目—答案匹配引擎。当前最应优先修复的不是相似度参数，而是文档级安全门控和题目结构识别。

## 八、测试边界

- 按用户要求，本轮没有进行平板真机测试。
- 本轮评估题目与答案的定位关系，不评估 573 份答案的数学推导是否正确。
- 2023 全书使用独立书签金标准；2025 习题册没有题级书签，结论由答案册 573 个题级书签、文本覆盖统计和代表性页面人工扫描共同支持。
- 2025 未执行外部 OCR，因为当前产品代码路径并未接入 recogniser；强行用外部 OCR 代跑会掩盖真实的产品行为。
